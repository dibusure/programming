# programming

Личная коллекция исходников с отдельным сайтом для чтения. Подсветка Pygments, дерево папок, поиск по именам и путям, фильтр по языку, **Catppuccin Latte и Mocha** с переключением, ссылки на строки, копирование и скачивание оригинала.

**Это просмотр исходного кода, а не среда его выполнения.** Программы из `code/` не импортируются и не запускаются при сборке или просмотре. Markdown пока показывается как исходник, без преобразования в статью.

## Темы: Catppuccin Latte и Mocha

В правом верхнем углу находится переключатель **Latte / Mocha**. Latte — светлая,
Mocha — тёмная; активная кнопка выделена. Палитра меняется одновременно у интерфейса,
дерева файлов и подсветки кода, в том числе Haskell. Обе темы используют официальные
цвета Catppuccin с акцентом Mauve.

При первом посещении тема следует системному оформлению. После нажатия на кнопку
выбор сохраняется в `localStorage`, переживает перезагрузку и переходы между файлами,
а также синхронизируется между вкладками одного сайта. Сохранённые значения `light`
и `dark` из прежней версии понимаются как Latte и Mocha. На разных доменах выбор
хранится независимо. Если браузер запрещает хранилище, переключение всё равно работает
на текущей странице, но сохранение между переходами недоступно.

Палитра применяется до загрузки CSS, чтобы сохранённая тёмная тема не вспыхивала
светлым фоном. Без JavaScript страницы и код доступны в Latte; переключатель скрыт.
Никаких новых зависимостей или внешних запросов ради тем нет.

- `site/assets/style.css` — обе палитры и оформление интерфейса; основной акцент задаёт `--accent`.
- `site/assets/syntax.css` — цвета токенов Pygments через общие переменные палитры.
- `site/assets/theme.js` — начальный выбор, переключение и сохранение темы.

Палитры: [Catppuccin](https://catppuccin.com/palette/).
Рекомендации: [официальный style guide](https://github.com/catppuccin/catppuccin/blob/main/docs/style-guide.md).

## Ссылки на папки

У каждой папки в \`code/\` есть своя страница: [файловый менеджер](https://dibusure.github.io/programming/folders/).
Например, \`code/olymp/\` доступна по адресу
\`https://dibusure.github.io/programming/folders/olymp/\`.
Ссылку можно открыть напрямую и отправить другому человеку — он увидит файлы и подпапки.

В боковом дереве стрелка раскрывает папку, название открывает её страницу
(либо \`README.md\`, если он лежит в папке), а значок ссылки рядом ведёт
именно на страницу папки. На странице есть хлебные крошки и кнопка
«Скопировать ссылку». Ссылки работают на GitHub Pages и Cloudflare Pages.

## Добавить программу

Положи файл в `code/`, сохрани в UTF-8 и сделай коммит в `main`. Внутри этой папки можно создавать любую структуру:

```text
code/
├── haskell/
│   └── Main.hs
├── python/
│   └── solution.py
├── cpp/
│   └── solution.cpp
└── projects/
    └── example/
        └── main.rs
```

После включения Pages сайт будет обновляться при каждом push в `main`. Ничего копировать в Markdown не нужно. Демонстрационные файлы из `code/examples/` удалены; добавляй только нужные исходники.

## Первый запуск: GitHub Pages

1. Открой **Settings → Pages** в этом репозитории.
2. В **Build and deployment → Source** выбери **GitHub Actions**.
3. Открой **Actions → Publish code gallery → Run workflow → main → Run workflow**.

После успешного `deploy` адрес сайта будет `https://dibusure.github.io/programming/`. Пока Pages не включён и публикация не завершена, по этому адресу может быть 404. Если первый автоматический запуск завершился ошибкой `Configure Pages`, включи Pages и запусти workflow заново.

Сборка и тесты выполняются также для pull request, но PR не публикуются на основной сайт. Токен GitHub не нужен в конфигурации сайта; workflow использует стандартные разрешения GitHub Actions.

## Локальный просмотр — через uv

```bash
git clone https://github.com/dibusure/programming.git
cd programming
uv run --locked python site/build.py
uv run --locked python -m http.server 8000 --bind 127.0.0.1 --directory dist
```

Открой `http://localhost:8000`. Для новой сборки снова выполни `uv run --locked python site/build.py`. Автопересборки при локальном редактировании нет. `uv` создаёт отдельное окружение `.venv`; установка в системный Python не нужна.

Проверка генератора:

```bash
uv run --locked python -m unittest discover -s tests -v
```

Необязательные тесты логики тем (нужен Node.js, пакеты npm не нужны):

```bash
node --test tests/theme.test.cjs
```

Node.js используется только для этих дополнительных тестов, а не для сборки сайта.

## Альтернатива: Cloudflare Pages

В **Workers & Pages → Create application → Pages → Connect to Git** подключи этот репозиторий. Используй именно **Pages**, не Workers.

| Настройка | Значение |
| --- | --- |
| Production branch | `main` |
| Framework preset | `None` |
| Root directory | корень репозитория, поле оставить пустым |
| Build command | `pipx run --spec uv uv run --locked python site/build.py` |
| Build output directory | `dist` |
| Environment variable | `SKIP_DEPENDENCY_INSTALL=1` |

В стандартном build image Cloudflare есть `pipx`. Эта команда запускает `uv` в изолированном окружении, даже если `uv` не установлен заранее. Версия Python задана в `.python-version`. После публикации Cloudflare покажет фактический адрес `*.pages.dev`. Сайт использует относительные ссылки и не требует отдельной настройки базового пути для разных хостингов.

Оба хостинга можно использовать параллельно. Если оставляешь только Cloudflare, отключи `Publish code gallery` в GitHub Actions, чтобы не запускать ненужную публикацию GitHub Pages.

## Языки и настройки

Pygments поддерживает более 500 языков и текстовых форматов, включая **Haskell (`.hs`) и Literate Haskell (`.lhs`)**, Python, C/C++, Rust, Go, Java, JavaScript/TypeScript, C#, Kotlin, Swift, Ruby, PHP, Lua и SQL. Подсветка выбирается по имени файла, а при неоднозначности также учитывается содержимое. Неизвестное расширение показывается как обычный текст. Для файлов с shebang предусмотрено дополнительное определение языка.

В `site.toml` находятся заголовок, подзаголовок, папка исходников, исключения и предел размера файла. Неоднозначный язык можно назначить вручную:

```toml
[lexers]
"*.hs" = "haskell"
"*.lhs" = "literate-haskell"
"*.h" = "c"
"special/example.txt" = "python"
```

Значения справа — aliases из списка языков Pygments. Если расширения нет в его списке, это не означает, что исходник нельзя показать: будет обычный текст без подсветки.

## Границы публикации

Публикуется только содержимое `code/`, а не весь репозиторий. Генератор пропускает скрытые файлы и папки, символьные ссылки, бинарные и не-UTF-8 файлы, файлы больше 512 КиБ, типичные папки зависимостей и некоторые имена файлов с секретами. Исключения можно изменить в `site.toml`.

**Это не проверка на утечки секретов.** Любой добавленный в публичный репозиторий пароль уже публичен, даже если сайт его не показывает. Не коммить ключи, токены и персональные данные. Не клади в `code/` файлы, которые не собираешься публиковать.

HTML и JavaScript показываются как экранированный текст. Кнопка скачивания выдаёт исходные байты в `.txt`-ресурсе с оригинальным именем через атрибут `download`; браузер не должен запускать исходник как HTML. Для отображения и копирования окончания строк нормализуются в LF, начальный UTF-8 BOM убирается. Скачивание сохраняет оригинальные байты.

Поиск работает по именам, путям и названиям языков, не по содержимому кода. Неизвестные и слишком большие файлы не ломают сборку; пропуски видны в логе. Для показа намеренно больших исходников увеличь `max_file_bytes` осознанно.

На сайте нет внешних шрифтов, CDN-скриптов, аналитики, backend или запросов к GitHub API. Просмотр страниц и подсветка работают без JavaScript; JavaScript нужен для поиска, переключения темы, копирования и переноса строк. Кнопка копирования требует разрешённого браузером буфера обмена; скачивание доступно независимо от него.

## Структура сайта

- `code/` — публикуемые исходники.
- `site/build.py` — генератор статических страниц.
- `site/assets/` — стили и небольшой JavaScript интерфейса.
- `site.toml` — настройки коллекции.
- `tests/` — регрессионные тесты генератора.
- `dist/` — результат сборки; в Git не хранится.
- `.github/workflows/pages.yml` — тестирование и публикация.
